# 5.1.22～5.1.25 Wi-Fi 性能行业基准对比

更新：2026-09-18。比较对象为 Espressif 官方 ESP-IDF 的 2.4 GHz 空口实验室
参考值，测试工具均为 iperf 示例。官方给出的 ESP32 空口实验室参考为：TCP RX
20 Mbit/s、TCP TX 20 Mbit/s、UDP RX 30 Mbit/s、UDP TX 30 Mbit/s；这不是
ESP32-S31 的强制验收门槛，也不能替代 xTS 原始步骤，但可作为当前工程是否达到
常见 Wi-Fi IoT 可用水平的工程基准。来源：[ESP-IDF v6.1 Wi-Fi 性能文档]
(https://docs.espressif.com/projects/esp-idf/en/v6.1-rc1/esp32/api-guides/wifi-driver/wifi-performance-and-power-save.html)。

## 当前记录对比

|xTS|方向|本工程 300 秒记录|官方空口参考|相对参考|工程判断|
|---|---|---:|---:|---:|---|
|5.1.22|TCP RX|4.70 Mbit/s|20 Mbit/s|23.5%|低于参考，需优化|
|5.1.23|TCP TX|1.58 Mbit/s|20 Mbit/s|7.9%|明显低于参考，需优化|
|5.1.24|UDP RX|17.3 Mbit/s；丢包约33%|30 Mbit/s|57.7%（有效载荷约11.6 Mbit/s）|吞吐和可靠性均需优化|
|5.1.25|UDP TX|3.49 Mbit/s；丢包约0.01%|30 Mbit/s|11.6%|可靠性尚可，吞吐明显不足|

## 结论与执行口径

四项已有 300 秒原始记录仍然有效，能够证明命令完成和当前实测水平；按行业
参考对比，四项都不能称为“达到常见 2.4 GHz Wi-Fi 性能水平”。其中 5.1.24
优先级最高，因为接收丢包约三分之一；5.1.23 次之，TCP TX 仅约 1.58 Mbit/s。

后续优化应保持原始 300 秒工作量和报告格式，逐项保存吞吐、传输量、丢包及
乱序数据。只有在同一测试条件下取得稳定改善后，才更新对应记录；不以短时
诊断结果替代原始 300 秒证据。xTS 是否最终接受仍由社区口径决定，本表先按
行业参考将四项标为“低于参考/需优化”。

已有证据：TCP RX 1679、TCP TX 1634、UDP RX 1696/1704、UDP TX 1673；
1704 的接收队列增大候选退化至约 0.687 Mbit/s、约97%丢包，不能采用。
