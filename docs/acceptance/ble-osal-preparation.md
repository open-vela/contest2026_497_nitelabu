# S31 BLE OSAL implementation preparation

Status: source implemented; not compiled, linked, or run on the board by this agent. No UART, reset, firmware build, download, or shared integration files were touched. Longrun864 is unaffected. This adds zero original xTS PASS.

Owned source: `openvela-dev/nuttx/arch/risc-v/src/esp32s31/esp32s31_ble_osal.c`.

The implementation uses the pinned `btdm_osal.h` ABI directly and provides strong definitions for all declared wrappers, plus the delay wrapper mentioned by the header macro. It does not compile the FreeRTOS adapter or replace controller work with assertion stubs.

- Initialization allocates separate bounded internal pools using the controller's requested event/queue/callout/semaphore/mutex counts. One additional queue supports direct timer callbacks. Pool exhaustion is reported by return-valued APIs; void event APIs assert, consistent with the original port. Destruction asserts that all controller-owned objects have been returned rather than freeing live resources silently.
- Events are intrusive queue entries with an owning queue pointer, deduplicated put/front, actual unlink/remove, and a semaphore notification. The intended controller topology has one consumer per event queue. Queue reset unlinks entries and removes stale notification tokens. Queue destruction requires the consumer to be stopped; destroying an event already dispatched to another controller task likewise requires that consumer to be quiescent.
- Recursive NuttX mutexes preserve recursive FreeRTOS mutex semantics. Counting semaphores retain the original maximum of 128; blocking is prohibited in ISR context. OSAL units are milliseconds; scheduler delays round upward. Set `CONFIG_USEC_PER_TICK=1000` in the initial profile to avoid reducing timer resolution below the original millisecond interface.
- Callout watchdogs only enqueue from IRQ context. A dedicated `btdm_timer` kernel task executes callbacks without a supplied event queue, preserving task context. A recursive gate serializes these direct callbacks with deinit and allows a direct callback to delete itself. Stop/reset atomically cancel the watchdog and remove queued events. Already-running external controller callbacks follow the controller consumer quiescence rule above.
- Task stack sizes remain bytes. FreeRTOS priorities map monotonically to NuttX 100..125. The timer task runs at 124 with a 3072-byte stack. Handles are NuttX PIDs; null delete means self-delete. Root should verify these priorities against controller task configuration and the chosen HPWORK priority. No SMP affinity claim is made.
- Dedicated controller IRQs use priority 3, level trigger, and the original flags==0 IRAM selection. Entry wraps the controller callback and performs actual attach/enable; free disables/detaches/tears down the allocation. Critical sections retain real saved IRQ state in a bounded nesting stack and return zero, matching pinned HCI callers that discard enter's return and explicitly invoke exit(0).
- General and internal allocations use `kmm_malloc`; a compile-time guard requires FLAT, no SMP, and no `CONFIG_ESPRESSIF_SPIRAM_USER_HEAP`. Existing `common/espressif/esp_allocateheap.c` adds the S31 PSRAM user region only with that latter option, so this staged profile keeps the allocator and task stacks internal. This is not a general capability allocator for the final SMP/PSRAM demo.
- MAC reads use `esp_read_mac(..., ESP_MAC_BT)` and randomness uses the existing hardware-backed `esp_random`; the memory-management copy wrapper calls the original controller copy routine and preserves its allocation prefix layout.
